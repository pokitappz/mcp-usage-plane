Docs

Start with the free meter. Add the plane when you need the operations.

The reference documentation lives with the code it describes, where it is version checked and cannot drift from what you actually installed. This page is the map.

Step one, no account needed

Meter your server.

A Rust MCP server takes the Tower layer directly. Anything else runs behind the sidecar, which fronts a server written in any language and speaks the same contract.

In a Rust server

cargo add mcp-usage-kit

In front of any server

cargo install mcp-usage-edge

This is the whole of the free path. It records terminal delivery rather than counting requests, it has no licence key, and it does not report to us.

mcp-usage-kit

The public facade and a runnable rmcp example. Start here.

mcp-usage-core

Protocol classification, pricing, terminal delivery, task attribution, quota and spend cap decisions. No I/O.

mcp-usage-tower

API key authentication, header and version guards, authorization aware caching, SSE observation, metrics.

mcp-usage-export

Synchronous recording, concurrent aggregation, idempotent retry, and a provider neutral meter event exporter.

mcp-usage-store

Atomic Redis, Valkey and PostgreSQL task attribution, for servers scaled horizontally.

mcp-usage-edge

The metering sidecar. This is the piece that talks to UsageKit Cloud.

Step two, with an account

Point the sidecar at the plane.

Provisioning hands you two credentials with deliberately different reach. The edge token goes to your sidecars and cannot read or change pricing. The admin token manages tenants, prices and export configuration, and never belongs in a sidecar's environment. 

PLANE_URL=https://usagekit.cloud
PLANE_EDGE_TOKEN=mup_edge_...

The sidecar pulls a snapshot of who may call and at what price, then posts idempotent usage aggregates back. Both directions are pull based and carry no session state, so if this service is unavailable your hot path keeps serving from the snapshot it already has.
