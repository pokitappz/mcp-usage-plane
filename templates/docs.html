Docs

Start with the free meter. Add UsageKit Cloud when you need the billing run.

The reference documentation lives with the code it describes, where it is version checked and cannot drift from what you actually installed. This page is the map.

Step one, no account needed

Meter your server.

A Rust MCP server takes the Tower layer directly. Anything else runs behind the proxy, which sits in front of a server written in any language and speaks the same contract.

In a Rust server

cargo add mcp-usage-kit

In front of any server

cargo install mcp-usage-edge

This is the whole of the free path. It records a billable event only once a result has actually been delivered, rather than counting requests. No licence key, and it reports nothing to us.

mcp-usage-kit

The public facade and a runnable rmcp example. Start here.

mcp-usage-core

Protocol classification, pricing, delivery detection, task attribution, usage and spending limit decisions. No I/O.

mcp-usage-tower

API key authentication, header and version guards, authorization aware caching, SSE observation, metrics.

mcp-usage-export

Synchronous recording, concurrent aggregation, idempotent retry, and a provider neutral meter event exporter.

mcp-usage-store

Atomic Redis, Valkey and PostgreSQL task attribution, for servers scaled horizontally.

mcp-usage-edge

The metering proxy, for servers not written in Rust. This is the piece that talks to UsageKit Cloud.

Step two, with an account

Point your server at UsageKit Cloud.

Provisioning hands you two credentials with deliberately different reach. The edge token goes to your servers and cannot read or change pricing. The admin token manages customers, prices and export configuration, and never belongs in a server's environment.

Connecting Stripe takes a restricted key, and an ordinary secret key is refused. Create one in the Stripe dashboard with Create restricted key, grant write on billing meter events and nothing else, and paste it in. We call exactly one Stripe endpoint, POST /v1/billing/meter_events, so that one permission is all this ever needs. Attaching a Stripe access policy to the key is worth the extra minute.

If you would rather not hand over a Stripe credential at all, we can post your usage to your own endpoint instead, signed with a secret you choose, and you make the Stripe call. Set kind to webhook on the export destination. 

PLANE_URL=https://usagekit.cloud
PLANE_EDGE_TOKEN=mup_edge_...

Your server asks for a copy of who may call and at what price, then reports back the billable events it delivered. Reporting the same event twice counts once, so a restart mid-batch costs nothing. Both directions are initiated by your server and carry no session state, so if this service is unavailable your live traffic keeps being served from the copy it already has.
